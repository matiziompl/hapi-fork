# HAPI fork v1.5

Date: 2026-10-31

## Added

- A **Status and limits** button in the prompt card. It uses the existing
  composer toolbar layout settings, including hide, reorder and browser-local
  persistence. Clicking it leaves the prompt draft, attachments and schedule
  untouched, with loading and error feedback.
- Immediate `/status` reports in chat for every supported agent flavor.
  Antigravity also accepts `/quota` and `/usage`. These commands are included in
  autocomplete even when an older Runner cannot list its commands.
- Live Codex account limits via initialization and `account/rateLimits/read`
  on a separate short-lived app-server. No thread is loaded, resumed or changed.
- Live Antigravity quota groups via its separate native print-mode `/usage`
  command. Remaining percentages and reset times are displayed in a Markdown
  table; unknown values are not substituted with unused allowances.
- Reports for other integrations show session settings and explicitly state
  that account quotas are unknown. Account quotas are distinct from HAPI's
  existing token/cost usage ledger.

## Implementation and compatibility

The Hub intercepts immediate bare commands, persists consumed chat rows and
publishes the existing SSE events without putting a status prompt into the
model queue. Request IDs prevent duplicate reports after retries; concurrent
requests in one session share a probe. Reports use the existing shared agent
message envelope so the chat renders their Markdown, rather than flattening
them into a system-status label.

The fixed probe travels through the existing authenticated session Bash RPC.
It executes on the session machine, using that process's account environment;
the Hub does not read Runner paths or receive authentication files. Probe time,
output size and owned subprocess lifetime are bounded. Raw native errors are
not published in chat. The Node.js executable and the authenticated agent must
be available on the session machine's PATH. Antigravity must support structured
print-mode usage; API-key-only Codex accounts may not expose ChatGPT limits.

HAPI Runner implementation, transport protocols and package versions are
unchanged. No Runner update is required for this feature when its existing
session Bash RPC is available. Bare immediate status commands are reserved by
the Hub; commands with arguments, attachments or scheduling retain their prior
delivery behavior. Inactive sessions must be reopened before requesting status.
Existing histories and earlier staged changes were preserved.

- 207 focused Hub, in-memory API, message delivery, RPC and native subprocess
  tests passed. These include namespace isolation, request deduplication,
  active-turn preservation, consumption acknowledgements, autocomplete and
  explicit unsupported-provider handling for all remaining agent flavors.
- 106 UI tests passed, including button activation, the hidden preference,
  toolbar order, draft/attachment/schedule preservation and composer regressions.
- 23 status/probe tests passed again after the report-rendering fix; its
  envelope regression was observed failing before that fix.
- Hub and web TypeScript checks passed. Frontend and Hub builds, embedded web
  asset generation and standalone Hub compilation passed. The static UI
  detector reported no findings.
- Three version workflow tests and `version:check` passed. The fork counter
  was incremented once from `1.4` to `1.5`; the README footer uses that source.
- Local probes against the installed Codex and Antigravity returned structured
  account quota data without starting a model turn. Controlled fake native
  executables also verified the exact read-only requests and error handling.
- Vite reported chunks above 500 kB. The jsdom attachment harness reported
  unavailable IndexedDB; the UI test suite still passed.

No browser tests, production deployment, service restart, data migration,
Runner installation, commit or push were performed. The real Hub-to-Runner
round trip and visual behavior on Serweusz remain for operator verification.
