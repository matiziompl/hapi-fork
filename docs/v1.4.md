# HAPI fork v1.4

Date: 2026-10-31

## Fixed

- Added Runner-side Codex attachment for an explicitly resumed thread already
  loaded in the same user's default local Unix-socket app-server. Discovery
  verifies the socket owner, loaded thread ID and working directory, is bounded
  by a timeout and only reads state before selecting the existing endpoint.
- Such reopen uses the existing writer instead of starting another private
  app-server. Initial and TUI resume preserve the native model, MCP/developer
  configuration, collaboration settings and metadata.
- Borrowed-server shutdown and Hub-view archive preserve the external process,
  native pending-input queue and uploads still referenced by native work. Cleanup
  also preserves uploads when End races wrapper shutdown. Private-engine
  ownership and default cleanup remain unchanged.
- Hub recognizes the exact resumed thread's native `already has an active writer`
  refusal and returns the existing `resume_unavailable` code (HTTP 409) rather
  than generic HTTP 500. A matching active Hub session can still be selected
  during a reconnect race; unrelated thread errors retain their existing path.

## HAPI Runner changes and deployment limits

This release changes `cli/src/codex/shared`, which is used by Runner-started
sessions. Hub-only deployment is insufficient. A local artifact is prepared at
`.tools/runner-v1.4/bun-linux-x64-baseline/hapi`; the agent does not replace the
installed executable, restart services, or start an attached production wrapper.
The currently inspected Runner has no `HAPI_CLI_EXECUTABLE` override and uses
`/usr/local/lib/node_modules/@twsxtd/hapi/node_modules/@twsxtd/hapi-linux-x64/bin/hapi`.

A manual binary replacement may trigger the original Runner's automatic mtime
handoff/restart because its inspected environment does not disable version
handoff. Existing session reconnection and real Hub reopen therefore require
operator verification after installation. The read-only discovery probe and
mocked protocol tests do not prove that production attachment has been deployed.
The executable replacement affects the current container installation; keeping
the patch across container recreation requires including it in the Runner image
or its managed installation workflow.

Default-socket reuse is POSIX-only and scoped to a loaded thread in the matching
working directory. Unknown, inaccessible or differently hosted writers are not
forcefully migrated. Borrowed archive retains uploads deliberately; cleanup
requires ensuring that no native work still references those files.

Upstream package/protocol versions remain unchanged; the fork counter is `1.4`.
No browser/frontend build, production data change, native lock deletion, commit
or push was performed for this task. Earlier version histories remain intact.
