# HAPI fork v1.0

Date: 2026-10-31

## Added

- Full HAPI source tree based on `matiziompl/hapi` commit
  `f8e55fb930cde45dd4ef5cc5dd1fac0a047f38b8` (upstream package version 0.33.3).
  The previous workspace only contained deployment configuration and Hub state.
- The fork version counter in `shared/src/buildInfo.ts` (`FORK_VERSION`), initially
  `1.0`, separate from upstream `APP_VERSION` and communication protocol versions.
- An English README covering the fork, separate Hub/Runner deployment, development
  and release workflow. The footer is generated from `FORK_VERSION`, synchronized
  by `version:sync`, `version:bump`, and the frontend build.
- A version label at the bottom left of the authenticated web app.
- Collapsible code previews beside file operations. The frontend uses existing
  read/write/edit/patch payloads, with syntax highlighting, lazy rendering and
  limits of eight snippets, 80 lines and 8,000 characters per snippet. Pending or
  failed writes are labelled as proposed content; failed reads are not previews.
  Compound shell output is not attributed to a single file.
- Persistent project-specific agent instructions and Git publication workflow,
  preserving the earlier workspace instructions and Prometheus version policy.

## Changed

- Docker now compiles the local Hub with embedded frontend assets rather than
  installing an unmodified global npm Hub. The non-root UID, existing data mount,
  public address and allowed browser origins are preserved.
- Interactive shell and agent terminals use black surfaces, green text, subtle
  borders and scrollbar styling inspired by Downloadeusz. Explicit ANSI colors,
  input, quick keys and communication paths retain their existing behavior.
- The local Git baseline is the existing public fork history, rather than a new
  unrelated root commit. Data, secrets, dependencies and local tools are ignored.

## Fixed

- Codex reopen redirects to the already active conversation only when namespace,
  machine, directory and native thread all match. It does not start a duplicate
  runtime, delete or merge conversation rows, or bypass the runtime ownership lock.
- Reconnect races restore the source row's archive metadata before redirecting.
  Ambiguous or unavailable thread ownership returns `resume_unavailable` (HTTP 409)
  instead of treating the expected ownership refusal as an internal server error.
- Existing interactive Codex diff controls remain available alongside the new
  file-operation previews.

## Verification

- Final full frontend unit suite: **3,843 passed, 0 failed**, across 335 files.
- Version workflow: 3 tests passed, including `v1.9` to `v1.10`, idempotent README
  synchronization, stale footer detection and invalid version rejection.
- Hub session/cache/reopen and in-memory HTTP route regression tests: 253 passed,
  including 10 Codex ownership tests. No live Hub or Runner was contacted.
- Focused frontend regression tests: 81 passed across file previews, existing
  tool result rendering, Codex diff controls, card layout and terminal controls.
- Hub and frontend TypeScript checks passed.
- Frontend production build and compilation of the standalone Hub passed.
  A compiled smoke check read the embedded HTML and fork frontend assets without
  starting a server or accessing production data.
- The first full frontend test run found three failures: two new preview cases
  whose support was being implemented and a regression in existing Codex diff
  controls. All three passed in the focused rerun and final full suite after the fixes.
- The unit suite logs expected IndexedDB failure-path messages and jsdom limitations
  for canvas/navigation. No browser was launched; this is not a browser console check.

## Compatibility and limitations

- Runner implementation is unchanged. No Runner was installed or restarted.
  Upstream `APP_VERSION`, API formats and the runtime ownership guard are preserved.
- No Docker/Podman executable is available in this workspace, so the Docker image
  build and Compose startup require operator verification on Serweusz. Compilation
  and embedded-asset checks do not substitute for that deployment check.
- No browser, Playwright or Chromium test was run. Visual appearance, mobile
  viewport behavior and actual terminal/reopen interaction require manual review.
- If a live runtime is unknown or unavailable to the Hub, automatic redirection
  cannot safely select it. Reconnect the owner before retrying; no runtime lock is
  removed and no process is killed automatically.
- Local Node 18 is too old for Vite 7; the build script explicitly uses the pinned
  Bun runtime. Existing dependency warnings about Browserslist data and Rollup
  annotations do not prevent the build.
- No production deployment or GitHub publication was performed. A local commit
  cannot be authored until the user supplies the Git author name and email.
