# HAPI fork v1.8

Date: 2026-11-02

## ReOpen correction

- Fixed a Runner regression that returned a cached spawn success for a closed
  or archived Codex root while sibling roots kept its shared wrapper alive.
  No replacement session was started, so the Hub eventually reported
  `Session failed to become active`.
- Terminal shared-root webhooks now release that root's spawn acknowledgement,
  PID aliases and recovery entry. Sibling roots and their wrapper remain running.
  Late closure/exit callbacks cannot release a replacement root's spawn entry or
  report its process as already exited. Webhooks with a mismatched process-start
  marker are ignored; terminal webhooks never adopt an inactive root as live.
- Runner startup also repairs stale recovery entries left by v1.7 when the
  matching process generation, Hub and authentication scope explicitly record
  the root as inactive. Active, absent, pending or unreadable ownership evidence
  retains the existing duplicate-spawn protection.

## HAPI Runner changes and compatibility

- Changed only `cli/src/runner/run.ts` and its existing regression test file;
  retained the original spawn RPC, local webhook format and native ownership
  locks. Session IDs, conversation history and upstream package versions are
  unchanged. Hub and frontend behavior were not otherwise modified.
- Applying this fix requires an operator-managed Runner CLI update. Rebuilding
  the Hub alone does not replace the executable in `ai-workspace`. The local
  Linux x64 baseline build is
  `.tools/runner-v1.8/bun-linux-x64-baseline/hapi`; it is an ignored build artifact.
- Incremented `FORK_VERSION` once from `1.7` to `1.8`, synchronized README and
  documented the Runner update requirement. Selective copying requires a
  complete v1.7 source baseline on Serweusz.

## Verification

- Reproduced the regression before fixing it: the real Runner spawn/webhook
  closures returned success without creating a replacement child. Added
  regression coverage for close, archive, sibling preservation, stale callbacks,
  process generations and recovery of already affected sessions after restart.
- 151 CLI tests across seven files passed with the existing isolated unit-test
  configuration. Network/process boundaries were mocked; runtime bookkeeping
  used temporary files. No live Runner or Hub was started by these tests.
- 171 Hub tests across four files passed with in-memory stores, including close,
  Codex ownership checks, reopen rollback and PTY session-ID preservation.
- CLI TypeScript checking, three version-workflow tests, version consistency,
  Git whitespace checks and standalone Linux x64 CLI compilation passed.
- Selective-copy commands passed a temporary-fixture check with Docker mocked:
  all five files were copied, missing source files stopped before Docker calls,
  and target data, secrets, Git history and local settings were retained.
- Frontend build and browser tests were not run: no frontend implementation
  changed. Live close/reopen on Serweusz remains for the operator to verify after
  updating the Runner CLI. Uncertain ownership intentionally remains protected
  and may still require inspection rather than an automatic duplicate launch.

No production deployment, binary installation, service restart, production-data
change, commit or push was performed. The reference project was not modified.
