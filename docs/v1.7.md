# HAPI fork v1.7

Date: 2026-11-01

## Status display

- Replaced the Markdown status table with a compact Codex CLI inspired panel:
  aligned session fields, monospace text and accessible account-quota bars.
  Unknown limits remain explicit rather than being inferred from token usage.
- Added a validated `hapi-status` report inside the existing assistant-message
  envelope. Existing chat transport and native quota probes remain unchanged.
- Status timestamps use `Europe/Warsaw`, including daylight-saving changes,
  24-hour clocks, minute precision and no timezone suffix. Reset countdowns and
  Codex quota-window durations use minutes.
- Fixed the composer status button on HTTP origins without `crypto.randomUUID`
  by using the existing compatible ID helper. Drafts and attachments are retained.

## Close without archiving

- Added Close session to More Actions in both session rows and the chat header,
  separately from Archive. The conversation and uploads remain available.
- Added authenticated `POST /api/sessions/:id/close` and the additive session RPC
  `closeSession`. Success requires both an inactive session and closed metadata;
  out-of-order metadata updates are awaited. Old CLI versions return an explicit
  unsupported result, without falling back to archive or machine tree-kill.
- Codex closes only the selected Hub root, interrupts its active turn and releases
  only queue entries proven to originate in HAPI. Ownership survives ledger
  reloads. Other native clients' queued input, sibling roots and borrowed native
  daemons are retained. The close RPC does not wait on its own control promise.

## HAPI Runner changes and compatibility

- The shared local/remote loop stops through the current launcher's own control
  and awaits its cleanup, including requests during initialization or mode
  transitions. A preceding launcher's stale control is never used.
- Connected the existing lifecycle teardown hooks for Claude, Cursor, Copilot,
  Kimi, OpenCode and Grok. AGY and DSH retain their existing teardown paths.
- Pi now awaits process termination before reporting closure. Cursor legacy
  awaits process-tree verification even when the root's close event arrives
  early; ACP and Pi propagate unconfirmed termination as an error.
- Closed shared roots are removed individually from Runner tracking. Existing
  archive methods, protocols and upstream package versions are retained.
- Close requires an operator-managed CLI update on the Runner machine and
  reopening sessions started by an older CLI. Updating the Hub alone delivers
  the status improvements. No CLI installation or Runner restart was performed.

## Version and handoff

- Incremented `FORK_VERSION` once from `1.6` to `1.7`, synchronized README and
  updated the REST contract. Continuation prompts did not increment it again.
- `docs/v1.7-files.txt` lists the exact files changed in this iteration for
  selective copying and publication. It requires a complete v1.6 source baseline;
  it does not replace files missing from earlier iterations.
