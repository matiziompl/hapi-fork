# HAPI fork v1.3

Date: 2026-10-31

## Changed

- Required two separate paste-ready command blocks at the end of every report
  for a persistent change: Hub update, then Git after operator verification.
- Defined the update sequence: check source/destination and all selected files
  before stopping services; run `docker compose down` in `~/docker/hapi`; copy
  only the explicit changed/new files from `~/workspace/hapi` with relative paths
  intact; run `docker compose up -d --build`. Any failed step stops the sequence.
- Required preservation of destination Hub data, secrets and `.git`. The older
  whole-directory replacement script is documented as the previous workflow;
  it is not the recommended update mechanism. Partial copying requires the full
  application source to have already been installed in the target directory.
- Clarified that the operator must stage selected files in the preserved target
  Git index before committing after verification. Partial updates do not copy
  the workspace index or replace target history.
- Updated the corresponding English README instructions and the fork version
  from `1.2` to `1.3`. Previous version entries remain unchanged.

## Verification and limits

- The three version-workflow tests passed; version/README consistency and Git
  whitespace checks passed.
- Checked the supplied command block's Bash syntax and exercised its explicit
  file-copy operation in a temporary fixture. Selected files were updated while
  destination `data/`, `.env` and `.git` sentinels remained unchanged.
- No application behavior or Runner implementation was changed. No application
  build, browser tests, Docker operation, production copy, commit or push was
  performed. The native Codex active-writer issue remains unresolved.
